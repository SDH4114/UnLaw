# Rulings: desk Studio (plan Tasks 10-13)

Ruling: the worktree started on main (729c0b5); the branch was moved to 21acac0 (feat/studio-recording) before any work — the task names that base — none.
Ruling: Move to Trash / Show in Finder for a project use `/api/studio/action` with `{action, path}` instead of `{action, name}` — a project name could match a capture file; the path is validated as a known project folder and capture itself refuses to trash projects outside captures/projects (400) — a page sending `name` for a project gets 404.
Ruling: `/api/studio/stop` takes `{force: true}` → `ul capture stop --force` — the warnings strip offers it for a stuck recorder (spec 7.5); without it the page could not finish a stuck recording — none.
Ruling: `/api/studio/record` passes `--display` only when the body has `display` — the saved setup chooses the display; the old body keys stay one-off overrides — a page relying on the old implicit display 1 now gets the setup's display.
Ruling: project thumbnails = `ul capture thumb <first media/screen-*.mp4, else camera-*.mp4>`; audio-only projects answer 404 — capture already has a cached thumbnailer that takes a path — none.
Ruling: `/api/studio/setup` and `/api/studio/project` bodies may be 2 MiB (others stay 64 KiB) — layouts for every format and scene do not fit 64 KiB with images, texts and events — none.
Ruling: "unavailable without osascript" for Open project… is tested in-process (DeskFailureTests), not through the server — the server tests keep /usr/bin on PATH, where the real folder dialog would open on the Mac — none.
Ruling: the rewritten library test expects `/api/studio/library` to be empty after a recording — a recording is now a project folder, not a library file; exports land in recordings/ and show up there — none.
Ruling: `/media/asset?t=&name=` serves the Studio's own images (storage.root/studio/assets, PNG/JPEG only, no folders or symlinks) — the Record preview must show image and text sources before they are copied into a project; the plan listed no route for it — none.
Ruling: idle `/api/studio/status` adds `free_bytes` of the captures disk — capture reports it only while recording, the REC bar shows free space before a recording too — none.
Ruling: the live camera preview stays on while recording (the old page released it) — spec 9 says "kept during recording" and two readers of one camera were measured to work (spec 4); the old cjs case `camera_record` now asserts the new rule — if macOS refuses a second reader on some camera, the recording's camera track would fail and the page should release it again.
Ruling: plain drag moves a source, ⌥-drag pans inside a `cover` box (focus) — both on the same box need a modifier; moving is the common action — a user may not find panning without the hint shown under the preview.
Ruling: the screen area is typed as X,Y,W,H in points, not drawn on the preview — the page only knows the display's pixels, not its points (Retina scale), so a drawn rectangle could be wrong by 2x — less convenient than drawing.
Ruling: on the Studio Record tab the digit keys pick scenes instead of switching desk tabs (help text says so) — spec: keys 1-9 are scenes — 1-6 view switching does not work from that tab (tabs are still clickable, and it works on Projects).
Ruling: the sources list eye toggles the placement's `visible` in the current scene/format; the camera's `enabled` (record it at all) is a checkbox in its properties, images/texts have "in recordings" — scenes decide what is visible, the setup decides what is recorded — none.
Ruling: new image/text sources get a placement in every format and scene, visible only in the current one (top-right, 20 % wide) — layouts are per format and scene; showing a logo everywhere at once would surprise — the user shows it per scene with the eye.
Ruling: the screen preview snapshot is taken every 1 s idle and every 3 s while recording (old page: every 2 s idle, none while recording) — spec 9 — more screencapture runs; it stops when the tab is hidden or left.
Ruling: no real-browser check was possible (no Chrome/Chromium on this Mac for a headless run, no browser tool); instead a cjs case renders the whole Record tab into a small DOM and checks every panel — layout/CSS problems are not caught; Haos's manual check (plan Task 12 step 6) is still needed.
