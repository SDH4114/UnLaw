# Unlaw project notes

- License: GPL-3.0-or-later (`LICENSE`, `Cargo.toml`, `pyproject.toml`).
- Update: `ul update [--check] [--force] [--branch|--tag]` reinstalls `unlaw` and `ule` from GitHub with `cargo install --locked --force --git` into the running binary's prefix; it skips when the remote commit (`git ls-remote`) equals the build's commit, the build's cargo features match `core.features` and ule is installed, and sets `CARGO_TARGET_DIR=~/Library/Caches/unlaw/cargo-target` (unless already set) so both packages share dependency builds (keep crossterm/toml_edit features identical in both Cargo.toml files). It never touches user config, data or edited commands.
- Reinstall/remove (`rust/src/remove.rs`, raw system commands): both print what they do and need `y` on stdin (or `--yes`). `ul reinstall` deletes `~/Library/Caches/unlaw/cargo-target` (only when CARGO_TARGET_DIR is unset), installs main like `ul update --force`, and only after a successful build moves config.toml/ule.toml into `<config>/backups/reinstall-<time>/`, writes defaults keeping `core.features` and `storage.root`, takes default seeds out (`layout::reset_seeds`: untouched deleted, edited moved to the backup, symlinks kept) and runs the new `ul init`. `ul remove` boots out and deletes the `com.unlaw.agent` and `com.unlaw.awake` launchd jobs, removes skills, the ~/.zshrc shell block (not the PATH line), the Keychain token, the whole config dir, `~/Library/Caches/unlaw` and the binaries (`cargo uninstall`, then files); a storage.root outside the config dir and the HF cache are kept. `ul remove <name>` deletes `commands/<name>` (a symlink only as a link) and drops a default command from `core.features` so it is not reseeded; system, core and built-in (`lm`, `game`) names are refused. Tests (`tests/test_remove.py`) fake cargo, launchctl and security on a restricted PATH.
- Purpose: small macOS CLI that dispatches commands from `commands/<name>/` (entry point `main.py`, `main.sh`, `main.js` or executable `main`, checked in that order).
- Core: Rust crate (`Cargo.toml`, `rust/src`), binaries `ul` and `unlaw` (plus `ula`/`unlawagent` = `ul agent ...`, `run_agent` in `lib.rs`); deps limited to `toml_edit`, `sha2`, `libc`, `crossterm` (games, `ul features choose`), `serde_json` (`ul lm` API). Dispatcher, config, system commands, completion, doctor, shell integration and project templates live there. Current release is 3.19.1 (`ul --version` adds the build commit); `Cargo.toml` and `src/unlawful/__init__.py` versions must match (build.rs enforces it).
- Commands: Python 3.11+, standard library only. `src/unlawful` holds seeded command sources, their help (`command_help.py`), legacy hashes and `DEFAULT_CONFIG`; `rust/build.rs` runs `rust/gen_assets.py` to embed them, so build needs Python 3.11+. System command help lives in `rust/src/help.rs`.
- Command contract: commands receive `UNLAW_COMMAND`, `UNLAW_COMMAND_DIR`, `UNLAW_CONFIG_DIR`, `UNLAW_STORAGE`, `UNLAW_BIN` (absolute path of the running ul); `main.py` runs with `UNLAW_PYTHON`, else `core.python`, else the newest `python3.x` on PATH. Descriptions for `ul commands --describe`/completion come from `help.txt`, the `main.py` docstring or a script's first comment, never by running the command. Changing a seed's content requires adding the previous release's hashes to `LEGACY_SOURCE_HASHES` (and the hash of any dev build installed on Haos's Mac). A copy that differs from an official source only in blank lines or the summary docstring also counts as untouched: `normalized_source` (Python `command_sources.py`, Rust `layout.rs`, kept identical) is compared with the current seed and with `LEGACY_NORMALIZED_HASHES`, generated from every commit's seeds; regenerate it when releasing. Tests that call unlawful code in-process must patch HOME/XDG_CONFIG_HOME/PATH first, or `load_config()` seeds the real `~/.config/unlaw`; `tests/ulbin.py` puts a failing fake `security` first on PATH.
- User data: `${XDG_CONFIG_HOME:-~/.config}/unlaw`; a source build and first non-help CLI invocation bootstrap it without overwriting user files.
- Extension rule: only system commands live in the dispatcher; every other command is seeded as standalone source into `${XDG_CONFIG_HOME:-~/.config}/unlaw/commands/<name>/main.py`. Legacy official import wrappers are migrated, but manually edited command files are never overwritten.
- Seeded sources contain only that command's logic and minimal config helpers/defaults; unrelated command code must never be concatenated into them.
- Configuration: `config.toml` is validated and atomically written with `toml_edit`, preserving comments and unknown keys; validation rules exist in both `rust/src/config.rs` and `src/unlawful/config.py` and must stay identical; aliases are token arrays, not shell strings.
- Test: `cargo test --workspace`, `cargo clippy --workspace --all-targets`, and `python -m unittest discover -s tests -v` (black-box tests build and run `target/debug/ul`; tests must never reach the network or real user tools — use fake executables on a restricted PATH and local servers).
- Build check: `cargo build --release --workspace`; install with `cargo install --path . --root ~/.local --force` and `cargo install --path ule --root ~/.local --force` (install.sh and `ul update` install both packages from GitHub with two `cargo install --git …` calls: unlaw with the chosen features, then ule).
- Project templates live in `templates/{commands,python,rust,cpp}` and may override generated files.
- Templates (working environments, `ul template save|edit|show|rm|list`, `ul <name> [--focus|--no-focus] [--dry-run]`): model and TOML in `rust/src/workspace.rs` (version 2: `path`, `focus`, `[[window]]` app/open/frame/screen/urls, `[[window.tab]] panes = [{dir, run, split}]`, strict unknown-key checks; the original `path`/`app`/`ai` files still load as `legacy` and launch exactly as before: `open -a <apps.editor|Obsidian> path`, then ChatGPT), commands and launching in `rust/src/template_cmd.rs`, the macOS side in `rust/src/desktop.js` (embedded, `osascript -l JavaScript -e <script>`, one JSON request on stdin so links/commands never reach argv; modes `snapshot` and `apply`). Launch: plan validates every folder first, apps open with `open -a` from Rust (testable), then one osascript run places frames (System Events, needs Accessibility), creates Ghostty windows/tabs/splits through Ghostty's AppleScript (`run` = `initial input` + newline so the pane stays a shell), opens browser windows (Safari/Chromium scripted; others via NSWorkspace) and hides other apps for focus. osascript is skipped when no window needs it. Ghostty/browser window ids go to `storage.root/runtime/templates.json` as `{id, pid, spec}`; a second run reuses a window only when the app pid is the same (browser ids restart after a relaunch) and `spec` (hash of kind/app/tabs/urls) still matches, so an edited template opens a new window; `rm` drops the entry. Placement only ever moves the window it opened or the one matching `open` (title contains its name or AXDocument equals it), never another window of the same app; a window the script does not answer for is a failure. One failing window never stops the others (exit 1). Frames are fractions of the display's visible frame (top-left global coordinates, screen 1 = main); `relative_frame` converts snapshots. Non-TTY `save` uses numbered prompts (tests), a TTY gets `checklist.rs`. The shell function cds unless `--dry-run` is among the args. Tests: `tests/test_templates.py` (fake osascript logging stdin); `tests/ulbin.py` puts a failing fake `osascript` first on PATH so no test reads or moves real windows. Security (from the audit, keep it): every string in a template is refused when it contains control characters, everything printed (`describe`, `list`, the save checklist) goes through `printable`, snapshot strings with control characters are dropped, `is_url` needs a letter first so `open` never gets an option, and `_template-path` exits 3 for a template named like a system/built-in/installed command or alias, so it never shadows `ul git`. `place` sets the size before the position: macOS will not narrow a window touching a display's right edge (measured with Ghostty).
- macOS Harness is optional; only `ul mac` and its doctor checks may depend on it.
- Git: `ul git` (seed = `src/unlawful/git_hosts.py` + `built_in_commands/git/main.py`; helpers are `_hosts_*` / `_git_*` so the concatenated seed has no name clashes). `ul git [msg]`, `push [msg]`, `commit`, `sync` all run add → secrets guard → commit (prompt when no message) → push; the guard unstages staged additions/changes (not deletions) named .env/.env.* (not .env.example), *.pem, *.key, *.p12, private id_rsa*/id_ed25519*, or > 50 MB and exits 1 unless `--allow-secrets`. Push = origin (a branch without upstream gets `-u origin <branch>`), then every `mirror-*` remote (`git push <mirror> HEAD`; a failing mirror only warns). `init` (refuses inside a work tree; `-b main`; merges a per-type .gitignore, never removing lines; first commit; `--connect`), `connect SPEC` (host name github/gitlab/codeberg/gitea → `create_repo`, private unless `--public`; otherwise `expand_remote`: `gh:`/`gl:`/`cb:` short forms, URLs, local paths; refuses to replace a different origin without `--force`; rerunning with the host origin already points to reuses it; SSH gate via `ssh_check`, offers `ensure_ssh_key` + key page; `ls-remote` check; push -u), `mirror add|list|remove`, `token HOST [--url]` (`prompt_token`: `security add-generic-password ... -U -w` with `-w` last, so security prompts and the token never enters argv; Keychain service `unlaw.git.<API server hostname>`, account unlaw, so a token is only ever sent to the server it was saved for; GitHub uses `gh auth login`), `open`, `pr` (pushes, then `gh pr create --fill` on GitHub when gh exists, else the host's compare/MR page), `undo [--list|COMMIT]` (soft reset to HEAD~1 or to COMMIT by hash/message part, refused when any undone commit is on a remote branch; `status`/`pull` were removed and refused with exit 2 so they never become commit messages). GitHub creation goes through `gh` with an explicit owner (`gh api user`); GitLab/Gitea/Codeberg through their APIs with the Keychain token, redirects never followed, the token scrubbed from every error, answers capped at 1 MB, server text stripped of control characters. Hardening from the security audit (keep it): API repo URLs go through `_git_checked_remote` and `ls-remote --end-of-options`; the guard unstages with `--literal-pathspecs reset --pathspec-from-file=-` and compares names casefolded; init refuses a symlinked .gitignore (O_NOFOLLOW); ssh_check uses `StrictHostKeyChecking=yes` (never accept-new). Tests: `tests/test_git_command.py` (real git, local bare remotes, stubbed hosts via `tests/fake_git_hosts.py`), `tests/test_git_hosts.py` (fake gh/security/ssh on PATH, local HTTP API).
- Desk: `ul desk` (seed: `src/unlawful/kanban.py` + `reminders.py` + `canvas.py` + `desk_ui.py` + `desk.py`). Terminal access for people and agents (no server): `list [--json]`, `show [board] [--json] [--reminders]` (the default board is `todo.vault_path` + `todo.file`; the `[todo]` config section stays for that), `add <text> [--column C]` (first column by default, `quick_text` dates), `move <n> <column>`, `done <n>` (to `todo.completed_column` or a Done-like column); add/move/done take `-b <board>`; card numbers count across all columns like `KanbanBoard.numbered_tasks`. The agent's `today`/`todo_list` read `ul desk show --json`, `todo_add`/`todo_done` run `ul desk add/done`. `ul todo` was removed in 3.17.0: `todo` is in `RETIRED_COMMANDS` (untouched seeds deleted on startup, edited kept) and in `features.RETIRED` (still valid in `core.features`, ignored; `FEATURE_RETIRED` in Rust). `ul desk --help` is kept short (under 30 lines, a test checks it); page details live in README. The page server serves the same board on 127.0.0.1 with stdlib `http.server`: Host check, random token (page `?token=`, API `X-Desk-Token`), CSP, no CORS. The file is the source of truth: every change carries the board version (sha256 of the bytes, also the ETag) and is refused with 409 + the fresh board when the file changed; the page polls every 2 s and retries a conflicting change once by card line and column name. The page (`desk_ui.py`, vanilla JS) builds nodes with textContent only, never innerHTML, because card text is user data. Look (3.19.1): amber/yellow on white or warm black; colors only through the CSS tokens in both themes (`--accent` is a fill with `--on-accent` text, `--accent-ink` is for text and lines on the page background, `--energy` orange marks focus/today); the board picker is a flat menu (`#boards`, `loadBoards`), not a `<select>`, because a macOS select opens around the chosen item and hid the boards above it. The logo is `assets/logo.svg` (white rounded square, amber `UL` drawn as strokes, no font; `assets/logo-dark.svg` is the same on #0b0b0a); desk_ui.py inlines both files as header marks (CSS shows the one for the theme) and as the favicon's `data-light`/`data-dark` (`applyTheme` swaps the href, because the page theme can differ from the system one). `DeskLogoTests` fails when the page and the files differ, so change a file and re-inline it. Pomodoro state is `storage.root/desk/pomodoro.json` under a flock (`.lock`), shared by the server's ticker thread (notifications via `osascript`) and `ul desk pomodoro`; finished focus sessions go to `pomodoro.jsonl`, recent boards to `recent.json`. Reminders layer (`reminders.py`, `desk.reminders`, default on; `ul desk --reminders`, board id `reminders:`): every Apple Reminders list is a column, every open reminder a card; it is a separate layer that never touches the .md boards (`Desk.layer`; `Desk.path` keeps the last file board). It goes through EventKit in a JXA script (`osascript -l JavaScript`, one JSON request per run, ~0.2 s); the Reminders app's Apple Events were measured at 12-22 s on a list with ~900 finished reminders, so never use them. Writes are two-way: add/edit (`@{date}` = due date, an existing time of day kept), move to another column = move to that list, done completes, delete removes, new column = new list; order inside a list is not settable, so same-column moves are no-ops; version = hash of the normalized snapshot, re-read fresh before every write. Boards folder: `desk.boards_dir` (default `boards`, relative to the config dir); a bare name (no `/`, no `.md`, not starting with `.`/`~`) means `<boards_dir>/<name>.md` in `ul desk`, `new`, `path`, `stats` and the page's "New board…" (folder created on demand); paths and `*.md` names keep their old meaning. Tests: `tests/test_desk_reminders.py` (FakeReminders subclass overriding `call`, fake `osascript` for the seed). Games tab: `Arcade` in desk.py runs at most one `$UNLAW_BIN game --stream` (validated game/level/size, own process group) and relays its NDJSON frames over `POST /api/game/stream` (fetch streaming, so the token stays in the header; one reader per session; blank keep-alive lines every 2 s detect a closed page, which kills the game); input is batched through `/api/game/input` and re-serialized from a whitelist; `/api/games` reads `arcade.toml` for the records. The page draws the cell grid on a canvas (box/block characters as shapes, edges pixel-snapped) and never reimplements a game. Studio tab: `Studio` in desk.py only calls `$UNLAW_BIN capture ... --json` (validated arguments; stop runs in a thread and reports through `/api/studio/status` `saving_done`), so terminal and page share one recording and library; `/media/{file,thumb,preview}` take the token as `?t=` (media elements cannot send headers), serve byte ranges (video seeking) and only files directly inside `captures/{screenshots,recordings}`. Canvas tab: `canvas.py` (stdlib, seeded with desk) reads/writes JSON Canvas `.canvas` files (Obsidian-compatible: nodes text/file/link/group, edges) and keeps every unknown key as read; Excalidraw-style drawings are the extra top-level `unlaw` = `{version: 1, elements: [...]}`, validated with caps (20000 elements/nodes/edges, 200000 points, 20000 text chars; bad input = ValueError = HTTP 400). Files are written tab-indented and atomically (mode kept); the version is `version_of(bytes)` like boards. Desk API: `GET /api/canvases` (canvas dir + recent `storage.root/desk/recent-canvas.json`, max 8), `GET /api/canvas[?path=]` (sets current, 404 `missing`), `POST /api/canvas` (whole document, 409 with the fresh canvas when the version differs; the only endpoint with a 16 MiB body limit), `POST /api/canvases` `{path, create}` (bare name = `<desk.canvas_dir>/<name>.canvas`, default `canvas` in the config dir; create never overwrites). `POST /api/canvas/new` creates the first free `canvas-N` (exclusive create), `/api/canvas/rename` `{path, name}` renames inside the same folder (hard link + unlink, never overwrites; version unchanged), `/api/canvas/choose` runs the macOS open dialog through `osascript` (`CHOOSE_CANVAS_SCRIPT`, folder in argv; `{path: null}` on Cancel, `{unavailable: true}` without osascript so the page asks for a path). Page: tools stay active until the user picks another; Photoshop-style keys read by `event.code` so any keyboard layout works (V select, H hand, N card, T text, U shapes + Shift+U cycle, B brush, G fill, E eraser, `[`/`]` width, D default ink, Cmd+G group, Cmd+0 fit, Cmd+=/- zoom); toolbar buttons are inline SVG icons (`CV_ICONS`, createElementNS); any color via `<input type=color>`; stroke width is a logarithmic slider 1-100 plus a typed number field (`cvTypedWidth`), `[`/`]` or `-`/`=` step it (validator allows strokeWidth 1-100). Clicking the active eraser or shape tool opens a bubble menu (`cvToolClick`/`cvOpenMenu`): eraser mode `object` (removes what it touches) or `part` (`eraseAt`/`cutElement` split the drawn strokes, rough wobble kept via `roughStrokes`; shapes become line/freedraw pieces, a filled shape leaves its fill as a paint element; text, cards and paint are not cut; Shift+E toggles), shapes evenness 3/2/1 = roughness 0/1/2. Eraser mode, evenness and width persist in localStorage `desk-canvas-tools`. Fill tool (`cvBucket`): renders the scene without UI into an offscreen canvas (`cvSnapshot`), floods the clicked color (`floodRegion`, tolerance 40, 4-connected), grows it 1 px and traces it (`traceMask` + Douglas-Peucker) into a `paint` element (`points` outer ring + `holes`, filled even-odd, stored in world units) inserted under an empty outline or above the filled shape it was poured into; a click on a line/text recolors it, cards/groups/edges get a `color`, an area reaching the view edge falls back to `applyFill` on the shape under it or `unlaw.background` (#rrggbb, validated); Alt+click clears (removes a paint). `tg download` keeps senders' file names, never overwrites and skips files already downloaded with the same size (also numbered copies `name 2.ext`); `capture` (`src/unlawful/capture.py`): screenshots and screen recording with `screencapture` (`-A` system audio, `-g` default mic, `-D` display, `-R` rect), camera/audio/non-default mic with ffmpeg avfoundation (`default` or names resolved from `-list_devices`; camera nv12 1280x720). Recording runs detached; `runtime/recording.json` holds the plan, segments and pids under `recording.lock`. Pause = stop the segment, resume = new segment; stop finishes each segment (camera overlay or mic mix, aligned by end time because all tools stop together), concatenates with `-c copy`, remuxes to MP4, then removes `captures/.parts/*`. Thumbnails and previews are written to a temporary file and renamed (never a half-written cached JPEG); any interruption while saving leaves phase `unsaved` with the parts kept; `--duration`/`--wait` save at once when a recorder dies. Recorders get SIGINT/SIGQUIT reset to default before exec (a parent with Ctrl-C ignored would otherwise make screencapture unstoppable) and are stopped SIGINT → SIGTERM → SIGKILL; a pid is only signalled when `ps` still shows the tool. Tests use fake tools (`FAKE_*` in `tests/test_command_paths.py`); `music`, `work`, and `yt` drive macOS apps/URLs.
- Telegram credentials: the bot token is in the macOS Keychain (account `unlaw`, service `telegram.keychain_service`), never in `config.toml`. If the Keychain has none, a `TELEGRAM_BOT_TOKEN=` line in `<config dir>/.env` is read (for people who prefer a file); nothing writes .env, and saving a token (`ul tg setup`, `ula setup`) removes that line so only one token is ever in use. `tg` and `agent` each carry this code (seeds are standalone).
- Local AI: `ul lm` is a Rust builtin (the CLI-only `/ul/job` endpoint requires `X-Unlaw-CLI: 1` and no `Origin`, so web pages cannot submit local-file jobs; memory admission reserves loading models) (`rust/src/builtin/lm/`) with its own MLX engines; LM Studio and Ollama are not used. Rust owns CLI, HTTP server (127.0.0.1 only, Host-checked, CORS only with `--cors`; OpenAI `/v1/*` incl. images/speech/videos + Ollama `/api/*`), model store (HF cache; converted models in `storage.root/models`) and supervisors: one worker process per lane (`core:chat`, `core:helper`, `core:video`, `image:image`, `bonsai-image:image`) with cross-lane memory accounting. MLX runs in `worker.py` (JSON lines over stdin/stdout) inside venvs built on uv-managed Python 3.13 from pinned `requirements*.txt` (core; mflux image; PrismML mflux fork for Bonsai Image); changing pins rebuilds that engine. GGUF models carry `Model.gguf` (file, mmproj, architecture from the header, runtime): chat/vision/embeddings run on a pinned, sha256-checked llama.cpp release (`llama-server` started per model by the worker), speech recognisers on `transcribe-cpp` (PyPI, core engine). Workers lead their own process groups; crashes, stops and signals kill the whole group so no llama.cpp server is left behind. API jobs never read local paths (`local` is set only for terminal jobs). A worker crash or OOM must never stop the server; there is never a cloud fallback. Tests use `UNLAW_LM_PYTHON` + `UNLAW_LM_WORKER` with a fake worker and `HF_HUB_CACHE`.
- Terminal arcade: `ul game` is built into the Rust core (`rust/src/builtin/game/`, crossterm): Tetris, Snake, Minesweeper and Space Invaders with mouse support, close to the originals, plus Chomp (`chomp.rs`), an original maze chase (not a Pac-Man copy: each level is a generated mirror-symmetric braided maze; hunters Hound/Fox/Owl/Moth with their own targets, rest/hunt phases, power-pellet fright, eyes back to the lair); games are state machines tested headlessly through the `Screen` trait. plus Dash (`dash.rs`), an original endless runner with the mechanics of the browser offline game (a fox, not a dinosaur: fixed-height gravity jump, duck lasting 0.35 s extended by key repeats, cacti and 2-frame birds at three heights, speed up to a per-difficulty max with gaps growing with the speed, night after 700 points; a bot test proves the gaps are always clearable). plus Ping Pong (`pingpong.rs`), old-arcade table tennis to 11: a mode menu (1 player vs a bot on the right / 2 players on one keyboard, last choice preselected via a static), ball and paddles on half rows (`Halves` draws ▀▄█), hit offset sets the angle, each hit speeds up, paddle motion adds spin, sub-steps ≤ 0.4 cell so a fast ball never tunnels; bot = reaction delay + aim error (+ edge aiming on hard) at ≤ the human paddle speed, balanced by a test against a scripted player (bot share of points easy < 0.25 < normal < hard > 0.5); the record is the winning margin vs the bot only. plus Chess (`chess/`: `board.rs` rules = 0..64 squares, pseudo-legal moves filtered by make/unmake, Zobrist hash for repetition, SAN, FEN, outcomes; `search.rs` bot = negamax alpha-beta, iterative deepening, quiescence, TT, null move, MVV-LVA + killers, piece-square eval; `mod.rs` screen): perft tests guard the move generator (start, Kiwipete, position 3), so never change `board.rs` without them passing. The bot runs on its own thread with a cloned board and a stop flag (dropped `Thinking` stops it) so the clock and the desk stay live; easy = depth 2 with ±150 cp noise, normal = 0.8 s/depth 4, hard = 3 s iterative deepening, each capped at 1/30 of the bot's clock; `hard_beats_normal` (#[ignore], ~8 min in release) checks hard stays hard. Layout picks square size 7x3, 5x2 or 3x1 (about square on screen); pieces on 7x3/5x2 squares are bitmaps drawn with quadrant block characters (`sprites.rs`, 10x6 and 6x4 pixels; the desk page paints quadrants as rectangles), `L` cycles shapes/glyphs/letters. `setup.rs`: start screen bot/friend → color white/black/random (bot only) → time control form (typed digits, Backspace = `Key::Backspace`, −/+, presets, on/off; click targets recorded per frame in `hits`; `remember` is skipped under cfg(test) so parallel tests see defaults); new `Color` variants (`BoardLight` ... `PieceBlack`) must be added to `terminal.rs` palette, `stream.rs` names and the desk PALETTE together; the desk page appends U+FE0E to chess glyphs so ♟ never becomes an emoji. Record = fewest moves to beat the bot (`lower_is_better`, `score_unit`; desk `SCORE_UNITS`). Key releases: `Input::Release` exists only for games that call `Screen::set_releases(true)` (returns whether releases really arrive): the terminal pushes kitty `REPORT_EVENT_TYPES` with DISAMBIGUATE and drops releases unless asked; `--stream` takes `{"release":k}` (desk page sends keyup, desk.py whitelists it); without releases a press moves a paddle for 0.12 s. Games turn releases off before pause/finish/leaving so menus never see them. Best scores live in `storage.root/runtime/arcade.toml`; `Scores::reload` rereads it before every menu, game and record, so the terminal and the desk (separate processes) share one table. `ul game --stream [--size RxC]` (`stream.rs`) is the same arcade on JSON lines (stdin: key/click/hover/resize, stdout: a frame of style runs only when it changed; closed stdin ends it) for `ul desk`. Presentation: `terminal.rs` `Renderer` is a double-buffered diff renderer (only changed cells, one synchronized-update write per frame, SGR only on style change; truecolor palette when `COLORTERM` says so, ANSI 16 otherwise, White/Gray always stay on the terminal theme); hover floods are merged, a panic hook/signal handler restores the terminal, kitty `DISAMBIGUATE_ESCAPE_CODES` is pushed only when the terminal answers. Games recompute layout each frame (`center_block`, HUD via `Screen::hud`, `wait_for_room` on resize), real-time games pace frames with `Ticker`; `Screen` additions (`dim_all`, `save_frame`/`load_frame`, `panel`, `hud`) have default implementations so the stream and test screens need not care.
- Storage: captures, Telegram downloads, and runtime files default to the single configurable `storage.root` (`data`, relative to the Unlaw config directory).
- Arcade difficulty: every game supports `easy`, `normal`, and `hard` (hard must stay genuinely hard); the default comes from `games.difficulty`.

- Awake: `ul awake` (seed: `src/unlawful/awake.py`, stdlib; the state format is documented at the top of that file). Sessions are `caffeinate -i -s [-d] [-t N | -w PID]` children of a detached supervisor (`awake.py _supervise <json>`, `start_new_session`) that writes `storage.root/runtime/awake.json` (atomic, flock `awake.lock`) and cleans up on SIGTERM/SIGINT/SIGHUP or when caffeinate ends. `-- cmd` has no supervisor: the foreground process runs the command, forwards SIGTERM/SIGHUP, ignores SIGINT like a shell and exits with the command's code; such a session is never replaced or stopped from outside (refused). Stale state (supervisor dead, or `ps` does not show `_supervise` plus this seed) is settled and ignored; a pid is only signalled after `ps` confirms it. `--lid` = `sudo -n /usr/bin/pmset -a disablesleep 1` through a sudoers rule that `ul awake lid setup` installs (`/etc/sudoers.d/unlaw-awake`, exactly the two `disablesleep 0|1` commands, `visudo -cf` first). `lid_previous == 0` means a restore is owed; a failed restore leaves a marker state (`lid_restore_failed`, no pids) that `status` shows and `off` retries. API for schedules: `Plan` (`source` = `manual` or `schedule:<id>`), `start_session`, `run_command`, `live_session`, `stop_session`, `status_info`. Tests (`tests/test_awake.py`) use fake caffeinate/sudo/pmset/visudo on a restricted PATH; no test touches real sudo or the lid. Schedules (`ul awake schedule add|list|rm`): `storage.root/runtime/awake-schedules.json` (`{version:1, schedules:[{id,start,end,days Mon=0|null,date|null,display,lid,name,created}]}`, atomic write under `awake-schedules.lock`; a damaged file is an error and is never overwritten; ids are max+1, never reused). One LaunchAgent `com.unlaw.awake` (`~/Library/LaunchAgents`, plistlib; `ProgramArguments` = `$UNLAW_BIN awake _scheduled`, so add/rm need `UNLAW_BIN`) has one deduplicated `StartCalendarInterval` per window start (launchd Weekday 0 = Sunday, ours is Mon=0, so `(d+1)%7`; one-offs use Month/Day, which launchd repeats yearly, hence past one-offs are dropped), `RunAtLoad` true (a window that is already open starts when the job is bootstrapped) and `AbandonProcessGroup` true (the session supervisor is a child of the job and must outlive it). add/rm rewrite it with bootout then bootstrap `gui/<uid>`; no schedules left = bootout and delete. `_scheduled [--now ISO]` (hidden; `--now` is for tests) checks that now is inside a window (yesterday's window too, it may cross midnight), not the exact start, because launchd runs a missed job on wake; of several open windows the one that ends last wins. It starts `until <end>` with source `schedule:<id>`; it never replaces a `command` session, never cuts short a session (manual or schedule) that ends later or has no end, does nothing when that schedule already runs until the same end, and replaces a shorter one. If the lid rule vanished, a `--lid` schedule still runs without the lid (logged); plain skips go only to `runtime/awake.log`. Past one-offs are dropped last: with schedules left the plist is only rewritten (no bootout, which would kill the running job), with none left it is booted out and deleted as the final step. `schedule rm` stops a session only when its `source` matches. `--lid` at add needs `lid_rule_works()`. A sleeping Mac is not woken at the start (no `pmset schedule wake`). `ul remove`, `ul remove awake` and `ul features remove awake` boot the job out and delete the plist (`remove_awake_job` in `rust/src/remove.rs`); the schedules file stays. Locks, always in this order: `awake-schedules.lock` -> `awake-start.lock` -> `awake.lock` (state) / `awake-lid.lock` (every pmset write and the rule probe, whose read+write-back is atomic). The start lock is held from `_prepare` until the supervisor (or the `-- command` state) is ready, so two starts never overlap and the second reads the real SleepDisabled; `_ensure_settle_job` and `_drop_idle_job` take the schedule lock, so they run after the start lock is released; the supervisor's `_finish` only tries the schedule lock without waiting (a scheduled run holding it while it replaces that very session would deadlock). Review hardening (keep it): the lid debt is on record BEFORE `pmset -a disablesleep 1` runs (`_prepare` writes a state owned by the CLI pid with `starting: true`, `lid_previous` 0; everything after `_prepare` in `start_session`/`run_command` is guarded by `except BaseException` -> `_finish`), so a SIGKILL/power loss leaves a stale state that any `live_session()` settles; `_scheduled` calls `_settle()` (stale state, `_lid_debt`) first, before it looks at windows, and a `--lid` session installs the login job even without schedules (`_ensure_settle_job`: plist with RunAtLoad and no StartCalendarInterval; `sync_job([])` keeps it while `_lid_owed()`; `_scheduled` and `off` remove it once nothing is owed and no schedules remain; `settle_job=False` in `_start_due` because `_scheduled` holds `awake-schedules.lock`, which is not re-entrant). `lid_rule_works()` runs `sudo -n /usr/bin/pmset -a disablesleep <current value>` (a no-op; an unknown value is never written), never `sudo -l`, which says yes for any NOPASSWD rule. The settle-only job also has `StartInterval` 300 (a supervisor killed without a reboot is repaid in 5 minutes) and is dropped by the supervisor's `_finish` when a lid session ends and nothing is owed. All `os.kill` go through `_signal` (a pid that just exited is fine). A scheduled start that replaces a shorter session ORs in its display/lid and does nothing when it would have to drop a lid it can no longer keep. `remove_job` unlinks the plist first, then boots out by label. `lid setup` is one `sudo` call of a fixed `/bin/sh -c SETUP_SCRIPT sh <rule text> <target>` (user data only as positional arguments, no user-owned file is read as root): root writes the text with umask 077 to a dot-named file in /etc/sudoers.d, chown/chmod, `visudo -cf` checks that file, `mv` moves it; user from `pwd.getpwuid(os.getuid())`; `ALL` and all-caps names are refused; sudo is `/usr/bin/sudo` (`UNLAW_AWAKE_SUDO` replaces it in tests only (kept as one variable: whoever can set the environment of `ul` already controls PATH and could interpose any tool, and the absolute path exists to defeat a writable PATH directory, which this variable does not reopen; `AwakeBase` sets it and puts fake sudo/pmset/launchctl/caffeinate/visudo first on PATH, and a test checks that nothing real is reachable)), and `UNLAW_AWAKE_SUDOERS` replaces the rule path in the Rust removal notes in tests only. State records `supervisor_lstart`/`caffeinate_lstart` (`ps -o lstart=` run with TZ=UTC and LC_ALL=C, because ps prints local time; an unknown value on either side never condemns a live session); a pid is signalled only when `ps` shows `<python> <this file> _supervise` (`-- command`: `<python> <this file>`; this file is searched for in the command line, so an interpreter path with spaces works) or `caffeinate` (or an interpreter running a script of that name, for the test fakes) as the program, and the start time still matches; a process that only mentions the name is never touched. State and schedule files are validated strictly (types, ranges, required keys, no bools as ints, no duplicate ids): a bad state counts as no session, a bad schedules file is an error naming the file and is never overwritten. `ul awake off` of any session (a schedule's or a manual one) records the windows open at that moment in `skipped` (`[{id, until}]` in awake-schedules.json, plus the session's own window) so `_scheduled` does not restart it before `until`; entries expire and go with their schedule. `ul remove`, `ul remove awake` and `ul features remove awake` only report the root-owned `/etc/sudoers.d/unlaw-awake` (existence check, no sudo).
