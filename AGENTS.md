# Unlaw project notes

- License: GPL-3.0-or-later (`LICENSE`, `Cargo.toml`, `pyproject.toml`).
- Update: `ul update [--check] [--force] [--branch|--tag]` reinstalls `unlaw` and `ule` from GitHub with `cargo install --locked --force --git` into the running binary's prefix; it skips when the remote commit (`git ls-remote`) equals the build's commit, the build's cargo features match `core.features` and ule is installed, and sets `CARGO_TARGET_DIR=~/Library/Caches/unlaw/cargo-target` (unless already set) so both packages share dependency builds (keep crossterm/toml_edit features identical in both Cargo.toml files). It never touches user config, data or edited commands.
- Reinstall/remove (`rust/src/remove.rs`, raw system commands): both print what they do and need `y` on stdin (or `--yes`). `ul reinstall` deletes `~/Library/Caches/unlaw/cargo-target` (only when CARGO_TARGET_DIR is unset), installs main like `ul update --force`, and only after a successful build moves config.toml/ule.toml into `<config>/backups/reinstall-<time>/`, writes defaults keeping `core.features` and `storage.root`, takes default seeds out (`layout::reset_seeds`: untouched deleted, edited moved to the backup, symlinks kept) and runs the new `ul init`. `ul remove` boots out and deletes the `com.unlaw.agent` launchd job, removes skills, the ~/.zshrc shell block (not the PATH line), the Keychain token, the whole config dir, `~/Library/Caches/unlaw` and the binaries (`cargo uninstall`, then files); a storage.root outside the config dir and the HF cache are kept. `ul remove <name>` deletes `commands/<name>` (a symlink only as a link) and drops a default command from `core.features` so it is not reseeded; system, core and built-in (`lm`, `game`) names are refused. Tests (`tests/test_remove.py`) fake cargo, launchctl and security on a restricted PATH.
- Purpose: small macOS CLI that dispatches commands from `commands/<name>/` (entry point `main.py`, `main.sh`, `main.js` or executable `main`, checked in that order).
- Core: Rust crate (`Cargo.toml`, `rust/src`), binaries `ul` and `unlaw` (plus `ula`/`unlawagent` = `ul agent ...`, `run_agent` in `lib.rs`); deps limited to `toml_edit`, `sha2`, `libc`, `crossterm` (games, `ul features choose`), `serde_json` (`ul lm` API). Dispatcher, config, system commands, completion, doctor, shell integration and project templates live there. Current release is 3.15.0-beta.2 (`ul --version` adds the build commit); `Cargo.toml` and `src/unlawful/__init__.py` versions must match (build.rs enforces it).
- Commands: Python 3.11+, standard library only. `src/unlawful` holds seeded command sources, their help (`command_help.py`), legacy hashes and `DEFAULT_CONFIG`; `rust/build.rs` runs `rust/gen_assets.py` to embed them, so build needs Python 3.11+. System command help lives in `rust/src/help.rs`.
- Command contract: commands receive `UNLAW_COMMAND`, `UNLAW_COMMAND_DIR`, `UNLAW_CONFIG_DIR`, `UNLAW_STORAGE`, `UNLAW_BIN` (absolute path of the running ul); `main.py` runs with `UNLAW_PYTHON`, else `core.python`, else the newest `python3.x` on PATH. Descriptions for `ul commands --describe`/completion come from `help.txt`, the `main.py` docstring or a script's first comment, never by running the command. Changing a seed's content requires adding the previous release's hashes to `LEGACY_SOURCE_HASHES` (and the hash of any dev build installed on Haos's Mac). A copy that differs from an official source only in blank lines or the summary docstring also counts as untouched: `normalized_source` (Python `command_sources.py`, Rust `layout.rs`, kept identical) is compared with the current seed and with `LEGACY_NORMALIZED_HASHES`, generated from every commit's seeds; regenerate it when releasing. Tests that call unlawful code in-process must patch HOME/XDG_CONFIG_HOME/PATH first, or `load_config()` seeds the real `~/.config/unlaw`; `tests/ulbin.py` puts a failing fake `security` first on PATH.
- User data: `${XDG_CONFIG_HOME:-~/.config}/unlaw`; a source build and first non-help CLI invocation bootstrap it without overwriting user files.
- Extension rule: only system commands live in the dispatcher; every other command is seeded as standalone source into `${XDG_CONFIG_HOME:-~/.config}/unlaw/commands/<name>/main.py`. Legacy official import wrappers are migrated, but manually edited command files are never overwritten.
- Seeded sources contain only that command's logic and minimal config helpers/defaults; unrelated command code must never be concatenated into them.
- Configuration: `config.toml` is validated and atomically written with `toml_edit`, preserving comments and unknown keys; validation rules exist in both `rust/src/config.rs` and `src/unlawful/config.py` and must stay identical; aliases are token arrays, not shell strings.
- Test: `cargo test --workspace`, `cargo clippy --workspace --all-targets`, and `python -m unittest discover -s tests -v` (black-box tests build and run `target/debug/ul`; tests must never reach the network or real user tools — use fake executables on a restricted PATH and local servers).
- Build check: `cargo build --release --workspace`; install with `cargo install --path . --root ~/.local --force` and `cargo install --path ule --root ~/.local --force` (install.sh and `ul update` install both packages from GitHub with two `cargo install --git …` calls: unlaw with the chosen features, then ule).
- Project templates live in `templates/{commands,python,rust,cpp}` and may override generated files.
- macOS Harness is optional; only `ul mac` and its doctor checks may depend on it.
- Git: `ul git` (seed = `src/unlawful/git_hosts.py` + `built_in_commands/git/main.py`; helpers are `_hosts_*` / `_git_*` so the concatenated seed has no name clashes). `ul git [msg]`, `push [msg]`, `commit`, `sync` all run add → secrets guard → commit (prompt when no message) → push; the guard unstages staged additions/changes (not deletions) named .env/.env.* (not .env.example), *.pem, *.key, *.p12, private id_rsa*/id_ed25519*, or > 50 MB and exits 1 unless `--allow-secrets`. Push = origin (a branch without upstream gets `-u origin <branch>`), then every `mirror-*` remote (`git push <mirror> HEAD`; a failing mirror only warns). `init` (refuses inside a work tree; `-b main`; merges a per-type .gitignore, never removing lines; first commit; `--connect`), `connect SPEC` (host name github/gitlab/codeberg/gitea → `create_repo`, private unless `--public`; otherwise `expand_remote`: `gh:`/`gl:`/`cb:` short forms, URLs, local paths; refuses to replace a different origin without `--force`; rerunning with the host origin already points to reuses it; SSH gate via `ssh_check`, offers `ensure_ssh_key` + key page; `ls-remote` check; push -u), `mirror add|list|remove`, `token HOST [--url]` (`prompt_token`: `security add-generic-password ... -U -w` with `-w` last, so security prompts and the token never enters argv; Keychain service `unlaw.git.<API server hostname>`, account unlaw, so a token is only ever sent to the server it was saved for; GitHub uses `gh auth login`), `open`, `pr` (pushes, then `gh pr create --fill` on GitHub when gh exists, else the host's compare/MR page), `undo [--list|COMMIT]` (soft reset to HEAD~1 or to COMMIT by hash/message part, refused when any undone commit is on a remote branch; `status`/`pull` were removed and refused with exit 2 so they never become commit messages). GitHub creation goes through `gh` with an explicit owner (`gh api user`); GitLab/Gitea/Codeberg through their APIs with the Keychain token, redirects never followed, the token scrubbed from every error, answers capped at 1 MB, server text stripped of control characters. Hardening from the security audit (keep it): API repo URLs go through `_git_checked_remote` and `ls-remote --end-of-options`; the guard unstages with `--literal-pathspecs reset --pathspec-from-file=-` and compares names casefolded; init refuses a symlinked .gitignore (O_NOFOLLOW); ssh_check uses `StrictHostKeyChecking=yes` (never accept-new). Tests: `tests/test_git_command.py` (real git, local bare remotes, stubbed hosts via `tests/fake_git_hosts.py`), `tests/test_git_hosts.py` (fake gh/security/ssh on PATH, local HTTP API).
- Personal commands: `todo` edits the configured Obsidian `TODO.md` (`done` falls back to a Done/Готово column when `todo.completed_column` is missing);
- Desk: `ul desk` (seed: `src/unlawful/kanban.py` + `reminders.py` + `canvas.py` + `desk_ui.py` + `desk.py`; `todo` is seeded from `kanban.py` + `todo.py`, so the parser exists once in the repo but each seed stays standalone) serves the same board on 127.0.0.1 with stdlib `http.server`: Host check, random token (page `?token=`, API `X-Desk-Token`), CSP, no CORS. The file is the source of truth: every change carries the board version (sha256 of the bytes, also the ETag) and is refused with 409 + the fresh board when the file changed; the page polls every 2 s and retries a conflicting change once by card line and column name. The page (`desk_ui.py`, vanilla JS) builds nodes with textContent only, never innerHTML, because card text is user data. Pomodoro state is `storage.root/desk/pomodoro.json` under a flock (`.lock`), shared by the server's ticker thread (notifications via `osascript`) and `ul desk pomodoro`; finished focus sessions go to `pomodoro.jsonl`, recent boards to `recent.json`. Reminders layer (`reminders.py`, `desk.reminders`, default on; `ul desk --reminders`, board id `reminders:`): every Apple Reminders list is a column, every open reminder a card; it is a separate layer that never touches the .md boards (`Desk.layer`; `Desk.path` keeps the last file board). It goes through EventKit in a JXA script (`osascript -l JavaScript`, one JSON request per run, ~0.2 s); the Reminders app's Apple Events were measured at 12-22 s on a list with ~900 finished reminders, so never use them. Writes are two-way: add/edit (`@{date}` = due date, an existing time of day kept), move to another column = move to that list, done completes, delete removes, new column = new list; order inside a list is not settable, so same-column moves are no-ops; version = hash of the normalized snapshot, re-read fresh before every write. Boards folder: `desk.boards_dir` (default `boards`, relative to the config dir); a bare name (no `/`, no `.md`, not starting with `.`/`~`) means `<boards_dir>/<name>.md` in `ul desk`, `new`, `path`, `stats` and the page's "New board…" (folder created on demand); paths and `*.md` names keep their old meaning. Tests: `tests/test_desk_reminders.py` (FakeReminders subclass overriding `call`, fake `osascript` for the seed). Games tab: `Arcade` in desk.py runs at most one `$UNLAW_BIN game --stream` (validated game/level/size, own process group) and relays its NDJSON frames over `POST /api/game/stream` (fetch streaming, so the token stays in the header; one reader per session; blank keep-alive lines every 2 s detect a closed page, which kills the game); input is batched through `/api/game/input` and re-serialized from a whitelist; `/api/games` reads `arcade.toml` for the records. The page draws the cell grid on a canvas (box/block characters as shapes, edges pixel-snapped) and never reimplements a game. Studio tab: `Studio` in desk.py only calls `$UNLAW_BIN capture ... --json` (validated arguments; stop runs in a thread and reports through `/api/studio/status` `saving_done`), so terminal and page share one recording and library; `/media/{file,thumb,preview}` take the token as `?t=` (media elements cannot send headers), serve byte ranges (video seeking) and only files directly inside `captures/{screenshots,recordings}`. Canvas tab: `canvas.py` (stdlib, seeded with desk) reads/writes JSON Canvas `.canvas` files (Obsidian-compatible: nodes text/file/link/group, edges) and keeps every unknown key as read; Excalidraw-style drawings are the extra top-level `unlaw` = `{version: 1, elements: [...]}`, validated with caps (20000 elements/nodes/edges, 200000 points, 20000 text chars; bad input = ValueError = HTTP 400). Files are written tab-indented and atomically (mode kept); the version is `version_of(bytes)` like boards. Desk API: `GET /api/canvases` (canvas dir + recent `storage.root/desk/recent-canvas.json`, max 8), `GET /api/canvas[?path=]` (sets current, 404 `missing`), `POST /api/canvas` (whole document, 409 with the fresh canvas when the version differs; the only endpoint with a 16 MiB body limit), `POST /api/canvases` `{path, create}` (bare name = `<desk.canvas_dir>/<name>.canvas`, default `canvas` in the config dir; create never overwrites). `ul todo` output must stay unchanged: the agent parses it. `tg download` keeps senders' file names, never overwrites and skips files already downloaded with the same size (also numbered copies `name 2.ext`); `capture` (`src/unlawful/capture.py`): screenshots and screen recording with `screencapture` (`-A` system audio, `-g` default mic, `-D` display, `-R` rect), camera/audio/non-default mic with ffmpeg avfoundation (`default` or names resolved from `-list_devices`; camera nv12 1280x720). Recording runs detached; `runtime/recording.json` holds the plan, segments and pids under `recording.lock`. Pause = stop the segment, resume = new segment; stop finishes each segment (camera overlay or mic mix, aligned by end time because all tools stop together), concatenates with `-c copy`, remuxes to MP4, then removes `captures/.parts/*`. Thumbnails and previews are written to a temporary file and renamed (never a half-written cached JPEG); any interruption while saving leaves phase `unsaved` with the parts kept; `--duration`/`--wait` save at once when a recorder dies. Recorders get SIGINT/SIGQUIT reset to default before exec (a parent with Ctrl-C ignored would otherwise make screencapture unstoppable) and are stopped SIGINT → SIGTERM → SIGKILL; a pid is only signalled when `ps` still shows the tool. Tests use fake tools (`FAKE_*` in `tests/test_command_paths.py`); `music`, `work`, and `yt` drive macOS apps/URLs.
- Telegram credentials: the bot token is in the macOS Keychain (account `unlaw`, service `telegram.keychain_service`), never in `config.toml`. If the Keychain has none, a `TELEGRAM_BOT_TOKEN=` line in `<config dir>/.env` is read (for people who prefer a file); nothing writes .env, and saving a token (`ul tg setup`, `ula setup`) removes that line so only one token is ever in use. `tg` and `agent` each carry this code (seeds are standalone).
- Local AI: `ul lm` is a Rust builtin (the CLI-only `/ul/job` endpoint requires `X-Unlaw-CLI: 1` and no `Origin`, so web pages cannot submit local-file jobs; memory admission reserves loading models) (`rust/src/builtin/lm/`) with its own MLX engines; LM Studio and Ollama are not used. Rust owns CLI, HTTP server (127.0.0.1 only, Host-checked, CORS only with `--cors`; OpenAI `/v1/*` incl. images/speech/videos + Ollama `/api/*`), model store (HF cache; converted models in `storage.root/models`) and supervisors: one worker process per lane (`core:chat`, `core:helper`, `core:video`, `image:image`, `bonsai-image:image`) with cross-lane memory accounting. MLX runs in `worker.py` (JSON lines over stdin/stdout) inside venvs built on uv-managed Python 3.13 from pinned `requirements*.txt` (core; mflux image; PrismML mflux fork for Bonsai Image); changing pins rebuilds that engine. GGUF models carry `Model.gguf` (file, mmproj, architecture from the header, runtime): chat/vision/embeddings run on a pinned, sha256-checked llama.cpp release (`llama-server` started per model by the worker), speech recognisers on `transcribe-cpp` (PyPI, core engine). Workers lead their own process groups; crashes, stops and signals kill the whole group so no llama.cpp server is left behind. API jobs never read local paths (`local` is set only for terminal jobs). A worker crash or OOM must never stop the server; there is never a cloud fallback. Tests use `UNLAW_LM_PYTHON` + `UNLAW_LM_WORKER` with a fake worker and `HF_HUB_CACHE`.
- Terminal arcade: `ul game` is built into the Rust core (`rust/src/builtin/game/`, crossterm): Tetris, Snake, Minesweeper and Space Invaders with mouse support, close to the originals, plus Chomp (`chomp.rs`), an original maze chase (not a Pac-Man copy: each level is a generated mirror-symmetric braided maze; hunters Hound/Fox/Owl/Moth with their own targets, rest/hunt phases, power-pellet fright, eyes back to the lair); games are state machines tested headlessly through the `Screen` trait. plus Dash (`dash.rs`), an original endless runner with the mechanics of the browser offline game (a fox, not a dinosaur: fixed-height gravity jump, duck lasting 0.35 s extended by key repeats, cacti and 2-frame birds at three heights, speed up to a per-difficulty max with gaps growing with the speed, night after 700 points; a bot test proves the gaps are always clearable). plus Ping Pong (`pingpong.rs`), old-arcade table tennis to 11: a mode menu (1 player vs a bot on the right / 2 players on one keyboard, last choice preselected via a static), ball and paddles on half rows (`Halves` draws ▀▄█), hit offset sets the angle, each hit speeds up, paddle motion adds spin, sub-steps ≤ 0.4 cell so a fast ball never tunnels; bot = reaction delay + aim error (+ edge aiming on hard) at ≤ the human paddle speed, balanced by a test against a scripted player (bot share of points easy < 0.25 < normal < hard > 0.5); the record is the winning margin vs the bot only. Key releases: `Input::Release` exists only for games that call `Screen::set_releases(true)` (returns whether releases really arrive): the terminal pushes kitty `REPORT_EVENT_TYPES` with DISAMBIGUATE and drops releases unless asked; `--stream` takes `{"release":k}` (desk page sends keyup, desk.py whitelists it); without releases a press moves a paddle for 0.12 s. Games turn releases off before pause/finish/leaving so menus never see them. Best scores live in `storage.root/runtime/arcade.toml`; `Scores::reload` rereads it before every menu, game and record, so the terminal and the desk (separate processes) share one table. `ul game --stream [--size RxC]` (`stream.rs`) is the same arcade on JSON lines (stdin: key/click/hover/resize, stdout: a frame of style runs only when it changed; closed stdin ends it) for `ul desk`. Presentation: `terminal.rs` `Renderer` is a double-buffered diff renderer (only changed cells, one synchronized-update write per frame, SGR only on style change; truecolor palette when `COLORTERM` says so, ANSI 16 otherwise, White/Gray always stay on the terminal theme); hover floods are merged, a panic hook/signal handler restores the terminal, kitty `DISAMBIGUATE_ESCAPE_CODES` is pushed only when the terminal answers. Games recompute layout each frame (`center_block`, HUD via `Screen::hud`, `wait_for_room` on resize), real-time games pace frames with `Ticker`; `Screen` additions (`dim_all`, `save_frame`/`load_frame`, `panel`, `hud`) have default implementations so the stream and test screens need not care.
- Storage: captures, Telegram downloads, and runtime files default to the single configurable `storage.root` (`data`, relative to the Unlaw config directory).
- Arcade difficulty: every game supports `easy`, `normal`, and `hard` (hard must stay genuinely hard); the default comes from `games.difficulty`.
- Built-in Rust commands (`zip`, `app`, `browser`, `game`, `lm`; `rust/src/builtin/`) resolve after `commands/<name>/`, so user folders override them; untouched old Python seeds (`RETIRED_COMMANDS`: known hashes, or known hashes ignoring blank lines or the summary docstring) are removed on startup. `app`/`browser` were seeds up to 3.8.0 (`tests/fixtures/{app,browser}-3.8.0.py`).
- Features (`ul features`; list in `src/unlawful/features.py`, embedded by `gen_assets.py` as `FEATURE_LIST` for `rust/src/features.rs`): the core (ul/unlaw, ule, system commands, zip, app, browser) is always installed; 22 optional features are chosen at install time and stored in `core.features` (default `["all"]` = everything incl. features of later releases; validated in both validators). `game`, `lm` and `agent` (only its `ula`/`unlawagent` bins, `required-features`) are cargo features (`default` = all, so plain builds and tests have everything; `cargo clippy --no-default-features --all-targets` must stay clean); every seed is a feature. `ensure_layout` seeds only chosen seeds and removes untouched unchosen ones (edited stay); with an unreadable config it only upgrades existing seeds. `ul update` passes `--no-default-features --features <chosen>` to unlaw and installs ule in a second `cargo install` (ule has no such features); it also rebuilds when the build's cargo features differ from the choice. Changing compiled features in `ul features` rebuilds the same commit (`--rev COMMIT`, short hashes work). install.sh carries a copy of the list (embedded Python chooser): `UNLAW_FEATURES` (names/`all`/`none`) wins, an existing `config.toml` keeps its `core.features` without asking (re-running the installer = update), otherwise a checklist on /dev/tty, or everything without a TTY; `tests/test_features.py` keeps the copy identical. The checklist widget is `rust/src/checklist.rs` (shared with `ul commands search`).
- Catalog: `ul commands search [words] [--list]` / `ul commands get <name>...` (`rust/src/catalog.rs`) read `catalog/index.json` + `catalog/<name>/main.py` from GitHub `main` via curl (`UNLAW_CATALOG_URL` overrides; tests use file://), verify sha256, write only when `commands/<name>` does not exist, and add downloaded features to `core.features`. `catalog/` is generated: `python3 -I rust/gen_assets.py --catalog src catalog`; regenerate whenever a seed changes (`tests/test_catalog.py` fails otherwise). The agent's `agent.commands` may name commands that are not installed; it then gets the "not installed" error.
- Rust user commands: `ul create command <name> --lang rust` writes a Cargo project; the runner rebuilds it when sources are newer than `target/release/<bin>`.
- Timed commands (`core.command_timeout` > 0, `rust/src/commands.rs`): the command runs in its own process group so a timeout kills its children too; when Unlaw owns the terminal, the child takes it with `tcsetpgrp` before exec and `Foreground` gives it back (otherwise `input()` and raw mode stop it with SIGTTIN/SIGTTOU). Tested on a pty in `tests/test_review_core.py`. Raw system commands only bootstrap the config layout (`ensure_config_layout`), so a broken `storage.root` can still be fixed with `ul config`.

- Every new or changed command must support `--help` and `-h` before any side effects, returning 0 and showing its purpose, all actions/options, defaults, dependencies and examples. Keep help accurate when behavior changes; include it in standalone seeded sources and command templates.
- YouTube downloads: `ul yt download <URL> [--format mov|mp4|raw] [--audio] [--quality <height>] [--output <directory>]` invokes optional external yt-dlp and ffmpeg/ffprobe, defaults to MOV in `storage.root/youtube` (`raw` keeps source codecs/container; `--audio` saves MP3; `--podcast` saves mono 64 kbps MP3 with metadata/cover into `yt.podcast_dir`, default iCloud Drive/Podcasts, and refuses when that folder's parent is missing so a disabled iCloud is never replaced by a local folder), and never downloads an entire playlist or overwrites existing files.

- YouTube subtitles: `--sub` or `--sub-lang [code]` saves only Markdown (original language if omitted); invalid codes list available tracks. Markdown starts with the video link and labels authored/automatic captions. `--full` saves video, separate MP3 and Markdown using one media download; unavailable/failed captions report an incomplete result while retaining saved media. Subtitle-only mode needs no ffmpeg.
- Archives: `ul zip` (Rust, `rust/src/builtin/zip.rs`) creates zip (default `zip.format`), 7z, rar (needs `rar`), tar.zst/xz/gz and auto-extracts by content; levels use one 0-9 scale (7-Zip names, default `max` = 7) mapped to each format's native settings, and media-heavy input without an explicit level drops to 1; 7-Zip is preferred with zip/bsdtar fallbacks. `--best` = level 9 in 7z (tar.xz without 7-Zip) unless -f/-o name a format. tar streams are piped into external compressors (measured on a 30 MB tree): zstd always `--long=27` (7-9% smaller, same speed, decodes with defaults), `xz -T0` (`-9e` at 9) when xz exists else bsdtar -J, 7-Zip deflate for tar.gz only at level 9 (~5% smaller, ~6x slower). Reading zstd tars pipes `zstd -d --long=31` into bsdtar, since bsdtar refuses windows above 128 MiB. 7z flags `-mqs`/`-mfb=273` were measured and made it worse. It never overwrites (adds " 2"), strips macOS junk unless `--keep-junk`, extracts multi-item archives into a folder, and feeds passwords via stdin, never argv.
- Skills: `ul skills` (`rust/src/skills.rs`, system command) writes an Agent Skill to `~/.agents/skills/unlaw` (`--project`, `--path`, `--claude` symlinks into `.claude/skills`). SKILL.md never hard-codes the command list: it tells agents to run `ul commands --describe` and `ul <cmd> --help`. `reference/<cmd>.md` is a snapshot from system/builtin help, `help.txt` or the shipped seed help (`SEED_HELP` from `gen_assets.py`); user commands are never run. Installs are tracked in `<config>/skills.json` with a fingerprint (version, commit, command names, entry/help mtimes); every normal run calls `refresh_if_stale`, so updates and new commands refresh it. Only folders with the `.unlaw-skill` marker are written or removed; alias expansions never appear in the skill.
- Agent: `ul agent` (= `ula`/`unlawagent`) is a seeded Python command (`src/unlawful/agent.py`, stdlib) on the OpenAI API of `ul lm serve` (autostarted; `UNLAW_AGENT_LM_URL` points it at another server and disables autostart, used by tests). CLI has three entry points: `ula [-p] [-c] [-m model] [message]` (pi-style console when stdin and stdout are TTYs, otherwise print mode; piped stdin becomes the message only when no message is given, so tests can feed approvals), `ula server` (Telegram + schedule in the foreground; `serve` stays as an alias because 3.3.0 launchd jobs call it) and `ula setup` (model with a tool-calling probe, token, owner, ids with add/`-id`/`-` editing, digest, roots, background on/off; writes config only when a value changes). The console UI lives in `src/unlawful/agent_ui.py` (seeded together with `agent.py`; `_clean_fragment` drops its import, including multi-line ones): a raw-mode `Editor` (bordered box, `/` and `@` menus from `Console.complete`, history in `storage.root/agent/history.txt`, bracketed paste, Ctrl+C clears/twice quits), `Keyboard` escape-sequence parsing, `MarkdownStream` (redraws each finished line styled; passes text through when colors are off) and `choose` for approvals (Yes / Yes for this tool kind this session / No). The console streams `/v1/chat/completions` over `http.client` on a reader thread; Esc (cbreak mode, `Keys`) or Ctrl+C shuts the socket, keys typed while it works are flushed, and `_close_open_calls` keeps history valid after a stop. Tools by level (`chat` none, `read`, `full`); every change (write/edit/move/delete to `~/.Trash`/run/`ul` outside `--help`) needs approval through the channel (console box, print-mode `[y/N]` on stdin, Telegram inline buttons to the owner, timeout = no). Paths must be inside `agent.roots` and never in keys/.env/keychain/config.toml/`storage.root/agent` (`protected()` is computed once per search). Telegram: owner = `telegram.chat_id`, others from `agent.allowed_ids` + `agent.users`; config is reread per update; answers go out as HTML (`telegram_html`) with a plain fallback; backlog from before start is skipped; `ula server` refuses while the launchd job runs (the job sets `UNLAW_AGENT_SERVICE=1`). Old tool results in saved sessions are clipped to 1500 chars. Probe results are cached per model in `storage.root/agent/models.json`; the console probes an unknown model at start and warns when it is chat only. `open_tasks` skips `todo.completed_column` and `DONE_COLUMNS` (Done, Готово, ...). Schedule, sessions, state, history and `audit.log` live in `storage.root/agent`; schedule changes take `schedule.lock` (flock) and damaged or zero-step jobs are skipped; due jobs move to their next time before running. Data flow: `app.rs` (terminal, event loop, mouse, suspend, hand-off) → `vim.rs` (`handle_key`: prompt/picker/explorer/popup first, then keymap.rs bindings, then vim's grammar `["x][count]op[count]motion|object`, insert mode, `.`/macros by replaying keys) → `edit.rs`/`commands.rs`/`ex.rs` mutate `Editor` (`editor.rs`: docs, views, `Layout` split tree, panel view, registers, search) → `ui.rs` draws a `Surface` that `render.rs` diffs onto the terminal. Documents are `Vec<String>` lines with char columns (`text.rs`); undo is a list of revisions of changes; highlight states are cached per line start (`document.rs`). Tests: unit tests per module plus headless key-scenario tests and a random-key fuzz test in `ule/src/tests.rs` (sandboxed HOME/XDG/ULE_UL; prompts, explorer and pickers are closed after every key so random keys never touch files; `ULE_FUZZ_ROUNDS`/`ULE_FUZZ_SEED` for long runs, `replay_debug` with `ULE_REPLAY` replays a sequence); `ULE_NO_CLIPBOARD=1` / `clipboard::disable()` keep tests off the real clipboard, `ULE_LSP_LOG=<file>` records LSP traffic. `ule/rustfmt.toml` (max_width 120) formats only the editor; the core is not rustfmt-formatted, so edit core files without reformatting them.

- Safety: seed migration/removal treats symlinked command folders and entry files as user-owned. Catalog installs reserve a new command folder after downloading and use exclusive writes, so concurrent commands are not overwritten. System and built-in help is printed before bootstrap/config validation.
- ule file safety: non-UTF-8 files are refused rather than decoded lossily; saves acquire temporary files exclusively. Explorer trash preserves the selected symlink and never resolves it to its target. Agent search validates both the visible path and resolved target against protected paths and roots.
