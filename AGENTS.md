# Unlaw project notes

- License: GPL-3.0-or-later (`LICENSE`, `Cargo.toml`, `pyproject.toml`).
- Update: `ul update [--check] [--force] [--branch|--tag]` reinstalls `unlaw` and `ule` from GitHub with `cargo install --locked --force --git` into the running binary's prefix; it skips when the remote commit (`git ls-remote`) equals the build's commit and ule is installed, and sets `CARGO_TARGET_DIR=~/Library/Caches/unlaw/cargo-target` (unless already set) so both packages share dependency builds (keep crossterm/toml_edit features identical in both Cargo.toml files). It never touches user config, data or edited commands.
- Purpose: small macOS CLI that dispatches commands from `commands/<name>/` (entry point `main.py`, `main.sh`, `main.js` or executable `main`, checked in that order).
- Core: Rust crate (`Cargo.toml`, `rust/src`), binaries `ul` and `unlaw` (plus `ula`/`unlawagent` = `ul agent ...`, `run_agent` in `lib.rs`); deps limited to `toml_edit`, `sha2`, `libc`, `crossterm` (games), `serde_json` (`ul lm` API). Dispatcher, config, system commands, completion, doctor, shell integration and project templates live there. Current release is 3.8.0 (`ul --version` adds the build commit); `Cargo.toml` and `src/unlawful/__init__.py` versions must match (build.rs enforces it).
- Commands: Python 3.11+, standard library only. `src/unlawful` holds seeded command sources, their help (`command_help.py`), legacy hashes and `DEFAULT_CONFIG`; `rust/build.rs` runs `rust/gen_assets.py` to embed them, so build needs Python 3.11+. System command help lives in `rust/src/help.rs`.
- Command contract: commands receive `UNLAW_COMMAND`, `UNLAW_COMMAND_DIR`, `UNLAW_CONFIG_DIR`, `UNLAW_STORAGE`, `UNLAW_BIN` (absolute path of the running ul); `main.py` runs with `UNLAW_PYTHON`, else `core.python`, else the newest `python3.x` on PATH. Descriptions for `ul commands --describe`/completion come from `help.txt`, the `main.py` docstring or a script's first comment, never by running the command. Changing a seed's content requires adding the previous release's hashes to `LEGACY_SOURCE_HASHES` (and the hash of any dev build installed on Haos's Mac). A copy that differs from an official source only in blank lines or the summary docstring also counts as untouched: `normalized_source` (Python `command_sources.py`, Rust `layout.rs`, kept identical) is compared with the current seed and with `LEGACY_NORMALIZED_HASHES`, generated from every commit's seeds; regenerate it when releasing. Tests that call unlawful code in-process must patch HOME/XDG_CONFIG_HOME/PATH first, or `load_config()` seeds the real `~/.config/unlaw`; `tests/ulbin.py` puts a failing fake `security` first on PATH.
- User data: `${XDG_CONFIG_HOME:-~/.config}/unlaw`; a source build and first CLI invocation bootstrap it without overwriting user files.
- Extension rule: only system commands live in the dispatcher; every other command is seeded as standalone source into `${XDG_CONFIG_HOME:-~/.config}/unlaw/commands/<name>/main.py`. Legacy official import wrappers are migrated, but manually edited command files are never overwritten.
- Seeded sources contain only that command's logic and minimal config helpers/defaults; unrelated command code must never be concatenated into them.
- Configuration: `config.toml` is validated and atomically written with `toml_edit`, preserving comments and unknown keys; validation rules exist in both `rust/src/config.rs` and `src/unlawful/config.py` and must stay identical; aliases are token arrays, not shell strings.
- Test: `cargo test --workspace`, `cargo clippy --workspace --all-targets`, and `python -m unittest discover -s tests -v` (black-box tests build and run `target/debug/ul`; tests must never reach the network or real user tools — use fake executables on a restricted PATH and local servers).
- Build check: `cargo build --release --workspace`; install with `cargo install --path . --root ~/.local --force` and `cargo install --path ule --root ~/.local --force` (install.sh and `ul update` install both packages from GitHub: `cargo install --git … unlaw ule`).
- Project templates live in `templates/{commands,python,rust,cpp}` and may override generated files.
- macOS Harness is optional; only `ul mac` and its doctor checks may depend on it.
- Personal commands: `todo` edits the configured Obsidian `TODO.md` (`done` falls back to a Done/Готово column when `todo.completed_column` is missing); `tg download` keeps senders' file names, never overwrites and skips files already downloaded with the same size; `capture` uses macOS `screencapture` and optional ffmpeg; `music`, `work`, and `yt` drive macOS apps/URLs.
- Telegram credentials: the bot token is in the macOS Keychain (account `unlaw`, service `telegram.keychain_service`), never in `config.toml`. If the Keychain has none, a `TELEGRAM_BOT_TOKEN=` line in `<config dir>/.env` is read (for people who prefer a file); nothing writes .env, and saving a token (`ul tg setup`, `ula setup`) removes that line so only one token is ever in use. `tg` and `agent` each carry this code (seeds are standalone).
- Local AI: `ul lm` is a Rust builtin (`rust/src/builtin/lm/`) with its own MLX engines; LM Studio and Ollama are not used. Rust owns CLI, HTTP server (127.0.0.1 only, Host-checked, CORS only with `--cors`; OpenAI `/v1/*` incl. images/speech/videos + Ollama `/api/*`), model store (HF cache; converted models in `storage.root/models`) and supervisors: one worker process per lane (`core:chat`, `core:helper`, `core:video`, `image:image`, `bonsai-image:image`) with cross-lane memory accounting. MLX runs in `worker.py` (JSON lines over stdin/stdout) inside venvs built on uv-managed Python 3.13 from pinned `requirements*.txt` (core; mflux image; PrismML mflux fork for Bonsai Image); changing pins rebuilds that engine. GGUF models carry `Model.gguf` (file, mmproj, architecture from the header, runtime): chat/vision/embeddings run on a pinned, sha256-checked llama.cpp release (`llama-server` started per model by the worker), speech recognisers on `transcribe-cpp` (PyPI, core engine). Workers lead their own process groups; crashes, stops and signals kill the whole group so no llama.cpp server is left behind. API jobs never read local paths (`local` is set only for terminal jobs). A worker crash or OOM must never stop the server; there is never a cloud fallback. Tests use `UNLAW_LM_PYTHON` + `UNLAW_LM_WORKER` with a fake worker and `HF_HUB_CACHE`.
- Terminal arcade: `ul game` is built into the Rust core (`rust/src/builtin/game/`, crossterm): Tetris, Snake, Minesweeper and Space Invaders with mouse support, close to the originals, plus Chomp (`chomp.rs`), an original maze chase (not a Pac-Man copy: each level is a generated mirror-symmetric braided maze; hunters Hound/Fox/Owl/Moth with their own targets, rest/hunt phases, power-pellet fright, eyes back to the lair); games are state machines tested headlessly through the `Screen` trait. Best scores live in `storage.root/runtime/arcade.toml`.
- Storage: captures, Telegram downloads, and runtime files default to the single configurable `storage.root` (`data`, relative to the Unlaw config directory).
- Arcade difficulty: every game supports `easy`, `normal`, and `hard` (hard must stay genuinely hard); the default comes from `games.difficulty`.
- Built-in Rust commands (`zip`, `game`, `lm`) resolve after `commands/<name>/`, so user folders override them; untouched old Python seeds (known hashes, or known hashes ignoring blank lines) are removed on startup.
- Rust user commands: `ul create command <name> --lang rust` writes a Cargo project; the runner rebuilds it when sources are newer than `target/release/<bin>`.

- Every new or changed command must support `--help` and `-h` before any side effects, returning 0 and showing its purpose, all actions/options, defaults, dependencies and examples. Keep help accurate when behavior changes; include it in standalone seeded sources and command templates.
- YouTube downloads: `ul yt download <URL> [--format mov|mp4|raw] [--audio] [--quality <height>] [--output <directory>]` invokes optional external yt-dlp and ffmpeg/ffprobe, defaults to MOV in `storage.root/youtube` (`raw` keeps source codecs/container; `--audio` saves MP3; `--podcast` saves mono 64 kbps MP3 with metadata/cover into `yt.podcast_dir`, default iCloud Drive/Podcasts, and refuses when that folder's parent is missing so a disabled iCloud is never replaced by a local folder), and never downloads an entire playlist or overwrites existing files.

- YouTube subtitles: `--sub` or `--sub-lang [code]` saves only Markdown (original language if omitted); invalid codes list available tracks. Markdown starts with the video link and labels authored/automatic captions. `--full` saves video, separate MP3 and Markdown using one media download; unavailable/failed captions report an incomplete result while retaining saved media. Subtitle-only mode needs no ffmpeg.
- Archives: `ul zip` (Rust, `rust/src/builtin/zip.rs`) creates zip (default `zip.format`), 7z, rar (needs `rar`), tar.zst/xz/gz and auto-extracts by content; levels use one 0-9 scale (7-Zip names, default `max` = 7) mapped to each format's native settings, and media-heavy input without an explicit level drops to 1; 7-Zip is preferred with zip/bsdtar fallbacks. It never overwrites (adds " 2"), strips macOS junk unless `--keep-junk`, extracts multi-item archives into a folder, and feeds passwords via stdin, never argv.
- Skills: `ul skills` (`rust/src/skills.rs`, system command) writes an Agent Skill to `~/.agents/skills/unlaw` (`--project`, `--path`, `--claude` symlinks into `.claude/skills`). SKILL.md never hard-codes the command list: it tells agents to run `ul commands --describe` and `ul <cmd> --help`. `reference/<cmd>.md` is a snapshot from system/builtin help, `help.txt` or the shipped seed help (`SEED_HELP` from `gen_assets.py`); user commands are never run. Installs are tracked in `<config>/skills.json` with a fingerprint (version, commit, command names, entry/help mtimes); every normal run calls `refresh_if_stale`, so updates and new commands refresh it. Only folders with the `.unlaw-skill` marker are written or removed; alias expansions never appear in the skill.
- Agent: `ul agent` (= `ula`/`unlawagent`) is a seeded Python command (`src/unlawful/agent.py`, stdlib) on the OpenAI API of `ul lm serve` (autostarted; `UNLAW_AGENT_LM_URL` points it at another server and disables autostart, used by tests). CLI has three entry points: `ula [-p] [-c] [-m model] [message]` (pi-style console when stdin and stdout are TTYs, otherwise print mode; piped stdin becomes the message only when no message is given, so tests can feed approvals), `ula server` (Telegram + schedule in the foreground; `serve` stays as an alias because 3.3.0 launchd jobs call it) and `ula setup` (model with a tool-calling probe, token, owner, ids with add/`-id`/`-` editing, digest, roots, background on/off; writes config only when a value changes). The console UI lives in `src/unlawful/agent_ui.py` (seeded together with `agent.py`; `_clean_fragment` drops its import, including multi-line ones): a raw-mode `Editor` (bordered box, `/` and `@` menus from `Console.complete`, history in `storage.root/agent/history.txt`, bracketed paste, Ctrl+C clears/twice quits), `Keyboard` escape-sequence parsing, `MarkdownStream` (redraws each finished line styled; passes text through when colors are off) and `choose` for approvals (Yes / Yes for this tool kind this session / No). The console streams `/v1/chat/completions` over `http.client` on a reader thread; Esc (cbreak mode, `Keys`) or Ctrl+C shuts the socket, keys typed while it works are flushed, and `_close_open_calls` keeps history valid after a stop. Tools by level (`chat` none, `read`, `full`); every change (write/edit/move/delete to `~/.Trash`/run/`ul` outside `--help`) needs approval through the channel (console box, print-mode `[y/N]` on stdin, Telegram inline buttons to the owner, timeout = no). Paths must be inside `agent.roots` and never in keys/.env/keychain/config.toml/`storage.root/agent` (`protected()` is computed once per search). Telegram: owner = `telegram.chat_id`, others from `agent.allowed_ids` + `agent.users`; config is reread per update; answers go out as HTML (`telegram_html`) with a plain fallback; backlog from before start is skipped; `ula server` refuses while the launchd job runs (the job sets `UNLAW_AGENT_SERVICE=1`). Old tool results in saved sessions are clipped to 1500 chars. Jobs have `kind`: `reminder` (default; the server sends the text, no model) or `task` (the agent runs the prompt); `parse_when` also takes Russian (`через 10 мин`, `завтра 9:00`). `/model` and `ula setup` probe tool calling and keep the previous model unless the user insists; `ula server` warns at start; tool calls a model writes as text (`<tool_call>` XML or a JSON block naming a tool) are parsed by `text_tool_calls` and run like real ones; when an answer claims or imitates an action (`pretends`: `CLAIMS`, `FAKE_CALL`, a tool name on its own line) and no tool ran this turn, `respond` sends one `NUDGE` and asks again, then adds `NO_TOOL_NOTE`. Probe results are cached per model in `storage.root/agent/models.json`; the console probes an unknown model at start and warns when it is chat only. `open_tasks` skips `todo.completed_column` and `DONE_COLUMNS` (Done, Готово, ...). Schedule, sessions, state, history and `audit.log` live in `storage.root/agent`; schedule changes take `schedule.lock` (flock) and damaged or zero-step jobs are skipped; due jobs move to their next time before running. Tests: fake streaming model and Telegram servers on localhost, console driven through a pty (`tests/test_agent.py`).
- Editor: `ule` is a separate crate in the workspace (`ule/`, root `Cargo.toml` has `[workspace] members = ["ule"]`), so its deps (`regex`, `unicode-width` on top of crossterm/toml_edit/serde_json/libc) never reach `ul`. Same version as Unlaw (a test reads the root Cargo.toml). Data flow: `app.rs` (terminal, event loop, mouse, suspend, hand-off) → `vim.rs` (`handle_key`: prompt/picker/explorer/popup first, then keymap.rs bindings, then vim's grammar `["x][count]op[count]motion|object`, insert mode, `.`/macros by replaying keys) → `edit.rs`/`commands.rs`/`ex.rs` mutate `Editor` (`editor.rs`: docs, views, `Layout` split tree, panel view, registers, search) → `ui.rs` draws a `Surface` that `render.rs` diffs onto the terminal. Background work (lsp.rs JSON-RPC clients per command+root, jobs.rs processes, picker file/grep scans, `ul commands`) sends `Event`s through `Editor::rx`. Documents are `Vec<String>` lines with char columns (`text.rs`); undo is a list of revisions of changes; highlight states are cached per line start (`document.rs`). Languages and themes are TOML (`ule/runtime/*.toml`, embedded) that `[languages.*]`/`[themes.*]` in `~/.config/unlaw/ule.toml` override; options, `[keys.normal|insert|visual|all]` bindings (command name, `:ex`, or keys) live there too (`config.rs`, `keymap.rs` DEFAULTS). Ordinary-editor keys live in `standard.rs` (`standard_keys`, default on): checked in `vim::handle_key` after overlays and before vim, but after ule.toml/default bindings for the same key; Shift-selection is visual mode with `vim.select_mode` (exclusive end, typing replaces it). ul integration (`ul.rs`): `:ul` runs into the `[ul]` panel buffer, `:ul!`/`:!`/`:terminal` hand the terminal over, `ask`/`ai_edit` pipe text to `ul lm "<prompt>"`, saving Unlaw's config.toml runs `ul config check`. `format_on_save = "auto"` formats only when the project has the formatter's config (so repos without rustfmt.toml are never reformatted). Tests: unit tests per module plus headless key-scenario tests and a random-key fuzz test in `ule/src/tests.rs` (sandboxed HOME/XDG/ULE_UL; prompts, explorer and pickers are closed after every key so random keys never touch files; `ULE_FUZZ_ROUNDS`/`ULE_FUZZ_SEED` for long runs, `replay_debug` with `ULE_REPLAY` replays a sequence); `ULE_NO_CLIPBOARD=1` / `clipboard::disable()` keep tests off the real clipboard, `ULE_LSP_LOG=<file>` records LSP traffic. `ule/rustfmt.toml` (max_width 120) formats only the editor; the core is not rustfmt-formatted, so edit core files without reformatting them.
- `ul edit` (`rust/src/editor.rs`, raw system command so it works with a broken config): `core.editor` (`"auto"` = ule next to ul or on PATH, then `$VISUAL`, `$EDITOR`, `open -t`; with an invalid config.toml the key is read straight from the TOML). `ul config edit` uses it and validates afterwards. Doctor has an `Editor` row. Tests that need the fallbacks run a copy of ul with no ule beside it (`CoreTestCase.ul_without_ule`).
- Plans for future work (`ul lm laya`, agent memory) are in `PLAN.md`.
